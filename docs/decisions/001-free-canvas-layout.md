# 001：自由画布采用稳定位置与受控碰撞

状态：已接受，核心布局规则已实施  
日期：2026-07-24

## 背景

现有布局同时追求自由摆放和自动重排。桌面持久化使用 8 列，但渲染与拖拽会根据宽度使用
10、8、6、4 或 2 列；新增、拖动、调整尺寸和数据归一化也使用不同算法。结果是预览、
保存和重载不一定保持一致，维护中需要反复修补推动逻辑。

## 决策

- NaviDash 继续采用自由网格画布，而不是自动流式布局。
- 桌面使用固定 8 个逻辑列，手机使用固定 2 个逻辑列。
- 用户移动组件发生单个同尺寸碰撞时优先交换位置。
- 其他碰撞只允许让局部碰撞链保持原列向下移动，最多影响四个现有组件。
- 超过影响上限或目标位置越界时，操作无效并回弹。
- 调整尺寸不得推动其他组件。
- 删除组件保留空位；点击新增寻找空位，拖拽到占用位置时可触发受控下推。
- 碰撞预览必须显示全部受影响组件，并与提交使用同一个确定性计算结果。

## 影响

- 用户获得稳定空间记忆和更可预测的编辑体验。
- 原有无限链式推动和横向自动避让已移除，替换为有影响上限的同列下推。
- 旧布局需要一次显式迁移，不能在普通渲染或视口变化时静默归一化。
- 自由度保留，但系统不再尝试替用户自动整理画布。
