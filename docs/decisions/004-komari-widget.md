# 004：Komari 采用服务端代理的只读摘要 Widget

状态：已接受，已实施  
日期：2026-08-26

## 背景

Komari 能提供节点在线和资源状态，适合在 NaviDash 首页快速扫读；但完整页面 iframe 会受到
登录 Cookie、`frame-ancestors`、移动端滚动和画布拖拽冲突影响。将实例地址或 API Key 交给
浏览器又会扩大凭据泄露和 SSRF 风险。

## 决策

- 新增 `komari` Widget，保持只读、低干扰，默认尺寸 `2×2`，可选 `2×1` 紧凑版与 `1×1`
  概览版；第一版不实现 iframe、浏览器直连 WebSocket、远程终端、任务执行、告警或管理能力。
- `2×2` 保留完整资源、容量和流量摘要；`2×1` 保留节点身份、运行时间、CPU/内存/硬盘百分比
  与可选实时上下行速率；`1×1` 只保留节点身份、运行时间和三项资源百分比。尺寸变体只裁剪展示，
  共用同一状态数据、轮询器和配置，不增加快照字段。
- NaviDash 服务端以 `KOMARI_BASE_URL` 和可选的 `KOMARI_API_KEY` 对 `/api/rpc2` 发起普通
  HTTP POST；使用 `public:getNodesInformation` 获取经脱敏的节点信息，并用
  `common:getNodesLatestStatus` 批量获取活跃节点的最新状态，再规范化为最小节点摘要。
- 每张 Widget 只能配置一个节点 UUID、网络速率显示开关和 `5`、`15`、`30` 秒刷新间隔。需要
  同时查看多台节点时添加多个 Widget，不将多张完整节点卡压缩到同一 Widget。配置、Snapshot、
  备份和客户端存储不得包含上游地址、凭据或原始状态数据。
- CPU、内存使用两列紧凑资源条，硬盘独占下一行以避免窄卡片中的标签换行与容量截断；启用网络
  信息时，累计下载流量/额度以横跨卡片底部、位于更新时间上方的进度条展示，并保留实时上下行
  速率。有限额度显示真实比例，无限额度使用柔和的连续渐变表示不设上限，缺失额度时不得伪造
  百分比；上下行速率与更新时间共用进度条下方一行，避免默认高度下内容溢出。
- `GET /api/komari/status` 接收多个同名 `nodeId` 查询参数，并仅返回 NaviDash 定义的稳定批量
  状态结构。可见页面共享一个轮询器，按活跃卡片的最短刷新间隔合并请求；页面隐藏暂停、恢复可见
  立即刷新。服务端必须限制超时和响应体、校验响应、隐藏上游细节，并合并相同短缓存窗口的请求。
- 上游节点 `region` 只在其值为两位 ISO 国家代码或标准双区域指示符国旗时，才规范化为最小的
  `regionFlag` 并显示在节点名之前；不得透传任意地区文本或 IP 地理信息。针对 Windows Chromium
  不原生合成国旗 Emoji 的情况，仅在国旗元素上使用随应用打包的 Twemoji Country Flags 子集字体，
  避免显示为 `US` 等两位字母，且不依赖运行时 CDN。
- 第一版不使用 RPC2 WebSocket，也不直接依赖 REST 兼容路由；仅在将来需要支持旧 Komari
  版本时，才为确定的“不支持 RPC2”错误增加受测试覆盖的 REST 回退。
- 点击 Widget 或节点时，客户端在新标签页打开 `GET /api/komari/open`；该端点仅重定向到固定的
  服务端实例地址，不在状态响应中传递该地址。
- 新增 Widget 类型不改变 Snapshot v2 的外层格式，因此不提升 `schemaVersion`。这只保证当前
  版本继续支持 `0.7.3` 基线；不支持旧版应用直接读取包含 `komari` 的新快照，回退时须恢复旧备份。
- 在首次写入 `komari` 前，存储层必须区分“快照文件缺失”和“存在但 Schema 不受支持或无效”。
  后一种情况必须阻止读写并报告可恢复错误，不能以空快照继续运行或覆盖原文件。仅升级
  `schemaVersion` 不足以解决旧版回退风险。

## 影响

- 用户可在首页查看有限节点的健康摘要，并在需要完整能力时跳转到 Komari。
- 凭据和上游连接细节留在服务端；多 Widget 刷新不直接放大对 Komari 的请求量。
- 实施需要扩展 Widget Schema、注册表、配置编辑器、双语文案、服务端 API、部署说明和测试。
